Security: what leaks, on the model

Fixed-versus-random Welch t-test on TCIM0's power model (tools/tvla_tcim0.py; 150,000 traces per group; pass below |t| = 4.5; green passes, red leaks).

This chip passes for the inputs, close to the limit and under the model's assumptions (5 µA measurement noise, 0.15 µA per flipping accumulator bit), but still leaks the weights' sparsity through the 2T2R read current. Only a different cell fixes that (next section). Programming leaks too (20,000 traces: |t| 65.67 with 2T2R, 66.38 with one-of-three; 4T4R not modelled): program weights in a trusted place.

Cell options: 2T2R, one-of-three, 4T4R

We did not move to 4T4R. This chip is 2T2R. The next-chip plan is the one-of-three cell (3T3R). Gemini's 4T4R (a summary written by Google's Gemini AI) also stores each trit as exactly one low-resistance device, but among four, so the fourth device is high-resistance for every value and carries no information.

Both one-of-three and 4T4R pass the weight test (150,000 traces, 5 µA noise, total supply current only); the model is not precise enough to rank them. 4T4R needs a third more devices than one-of-three for no measured gain, so the plan stays one-of-three. Neither cell fixes the programming leak, the deterministic LFSR or LOCK-after-reset. At 1 µA noise one-of-three is closer to the limit (4.08 on weights).

How it works

TCIM0 stores a 72 × 24 matrix of ternary weights (−1, 0, +1) and multiplies it by a 72-trit input vector, returning 24 sums from −72 to +72. One product replaces 72 TMAC.T instructions of REBEL-6.

Each weight is two ReRAM devices (2T2R): +1 sets the left one, −1 the right one, 0 neither. Each device is read as one bit, so the result is exact whenever every device reads correctly.

The test chip (SkyWater SKY130, sky130B with the ReRAM option, ChipFoundry's Caravan analog harness): 3,456 ReRAM devices, 48 sense amplifiers, the array controller, the logic, and a separate test cell with direct pad access. Programming voltages come from the board, so they can be changed after the first measurements.

TRITONE TPU: the Gen2 fixes

Fixes to the earlier TRITONE TPU (tpu_top_v2, now v2.4), in pull request #2:

  • Sparsity leak. The zero-weight counters (STATUS[31:16], PERF_CNT_1) were readable by any software. They are now hidden unless SEC (0x70) bit 0 opts in; bit 31 is a set-only LOCK.
  • Missed done bits. DONE was a one-cycle pulse that polling software could miss; it now stays set until the next start.

Verified on Verilator (results/ttpu_gen2/): new SEC test 11 checks, 0 failures; 4 of 4 existing TPU/SoC benches pass. Three existing benches needed their version checks updated to v2.4. Not yet: matrix results against a reference (the full-system simulation will do it).
